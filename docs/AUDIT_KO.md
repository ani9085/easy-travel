## 0. 요약

- `main`의 앱은 **한 화면(`app/page.tsx` 862줄, 클라이언트 컴포넌트 1개)** 에 부모님용 여행 중 기능과 보호자용 계획 기능이 섞여 있었습니다.
- 데이터가 `easy-travel-demo` · `easy-travel-planning` · `easy-travel-rates` 세 곳에 흩어져 있어 **계획 → 실행 → 리뷰가 이어지지 않았습니다.** 목적지도 계획 폼과 여행 설정 두 곳에 따로 있었습니다.
- 저장소가 공개 상태이고 서버에 OpenRouter 키가 있는데, **`/api/ai`에는 인증·출처 확인·횟수 제한·타임아웃이 없었습니다.** 운영 주소는 지금 Vercel Authentication(배포 보호)이 막고 있지만, 부모님이 쓰도록 보호를 끄면 그대로 노출됩니다.
- **Next.js 14.2.35는 14.x의 마지막 패치로 지원이 끝났고,** `npm audit`에서 critical(next) 1건과 high(postcss) 1건이 나왔습니다.
- 목적지와 상관없이 프랑스어 문장·유로·에어프랑스 후보가 나오는 정확성 버그가 있었습니다. 또 Vercel(UTC)에서 빌드하면 시각이 UTC로 박혀 **한국 브라우저에서 하이드레이션 불일치**가 났습니다.

P0 결함은 `claude/p0-hardening` 브랜치에서 고쳤습니다. 각 항목의 처리 상태는 아래 표 §2에 있습니다.

### 후속 구현 반영

이 보고서의 과거 “한 화면·Mock 기본값” 진단 이후 다음 변경이 `main`에 추가되었습니다.

- `/traveler`에 부모님용 여행 계획 입력 화면을 추가했습니다.
- `/guardian`을 스크롤형 단일 화면에서 메뉴별 화면으로 분리했습니다.
- 새 Trip은 빈 계획으로 시작하고, 저장된 Mock 장소·항공 후보는 실제 계획으로 복원하지 않습니다.
- `/api/ai`에 검증된 `trip_plan` 작업을 추가했습니다.
- `/api/flights/search`에 Duffel 실제 조회 어댑터를 추가했습니다. 토큰이 없으면 결과를 지어내지 않고 설정 오류를 반환합니다.
- 하루 2회 가격 감시 조건은 저장하지만, 실제 백그라운드 실행은 네이티브 APK의 WorkManager가 담당해야 합니다.

## 3. 보안·비용 점검 결과

- git 전체 이력에서 `sk-or-`·키 대입 패턴을 찾지 못했습니다(확인 완료).
- OpenRouter 키는 서버 환경변수에서만 읽고, 브라우저 번들에는 들어가지 않습니다.
- 가장 확실한 비용 상한은 **OpenRouter 대시보드에서 키별 사용 한도(credit limit)를 거는 것**입니다. 앱 안의 횟수 제한은 그다음 방어선입니다.
- 가족 접속 코드는 가족끼리 같은 값을 나눠 쓰는 공유 비밀입니다. 사용자별 인증이 아니라서, 서버 계정이 생기면(P2) 그쪽으로 옮겨야 합니다.

## 4. 배포 점검 결과

- 운영 주소 `easy-travel-dosl.vercel.app`은 Vercel Authentication으로 보호되어 외부 요청에 401을 돌려줍니다(2026-10-31 확인). GitHub Deployments API에는 기록이 없어 연결된 커밋은 Vercel 대시보드에서 확인해야 합니다.
- Vercel Hobby는 **비상업용**이고 Cron은 **하루 1회**까지만 됩니다.
- `OPENROUTER_SITE_URL`이 없으면 이제 요청 주소의 origin을 씁니다(전에는 `localhost:3000` 고정).
- 이번 브랜치는 **push하지 않았습니다.** push하면 Vercel이 미리보기 배포를 자동으로 만들 수 있으니 승인을 받은 뒤 진행합니다.
