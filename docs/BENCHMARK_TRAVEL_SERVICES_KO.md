# 여행 서비스 벤치마킹과 공동여행 UX

기준일: 2026-10-31 (Asia/Seoul)

이 문서는 easy-travel을 부모님 전용 앱으로 좁히지 않고, 가족·친구·커플·다세대 동행자가 함께 계획하고 여행 중 서로 돕는 서비스로 확장하기 위한 참고 문서다. 외부 서비스의 화면과 기능을 복제하지 않고, 사용자가 자연스럽게 다음 행동으로 이동하는 흐름을 벤치마킹한다.

## 1. 벤치마킹 대상

| 서비스 | 관찰할 강점 | easy-travel에 적용할 원칙 |
|---|---|---|

## 2. easy-travel의 공동여행 역할

하나의 여행에 여러 사람이 참여하고, 역할은 여행마다 바꿀 수 있어야 한다.

| 역할 | 권한 |
|---|---|
| 여행 소유자 | 여행 삭제, 참여자 초대·철회, 예약·비용 공유 범위 설정 |
| 공동 계획자 | 목적지 후보, 일정, 숙소 후보, 예산 제안·수정 |
| 여행자 | 본인 일정·예약·동의·체크인·위치 공유 설정 확정 |
| 보호자/관찰자 | 공유된 일정·안부·항공 상태 확인, 필요 시 도움 요청 |
| 보기 전용 초대자 | 확정 일정과 주소·시간만 확인 |

예약번호·결제금액·위치는 일정 공유와 별도로 권한을 둔다. 부모님이 여행자이면서 공동 계획자인 경우도 정상적인 기본 시나리오로 처리한다.

## 3. 권장 공동여행 흐름

```text
여행 생성
  → 가족·친구 초대
  → 각자 조건 입력
      (희망지·가능 날짜·예산·걷는 양·필수/선택 장소)
  → 후보와 항공 조건 비교
  → AI가 합의 가능한 일정 3안 제시
  → 제안·댓글·투표 또는 선택
  → 소유자가 예약과 일정을 확정
  → 예약정보를 사진·PDF·텍스트로 가져와 확인
  → 여행 전 체크리스트와 오프라인 여행팩 준비
  → 여행 중 오늘 카드·공동 체크인·도움 요청
  → 귀가 후 실제 지출 확인과 정산
```

여행 상태는 다음처럼 명시한다.

`초안 → 후보 비교 → 항공 감시 중 → 항공 예약 완료 → 일정 초안 → 일정 확정 → 여행 중 → 정산 검토 → 완료`

각 화면에는 `현재 상태`, `다음 행동 하나`, `누가 결정할지`를 먼저 보여준다.

## 4. 화면별 벤치마킹 포인트

### 여행 시작

- `목적지와 날짜를 알고 있음`
- `어디로 갈지 모르겠음`
- `항공권·여행계획서를 가지고 있음`

세 가지 시작점을 제공한다. 친구 여행은 “각자 조건 입력”을, 부모님 여행은 “큰 버튼으로 직접 입력”을 우선한다.

### 항공 비교·감시

- 날짜별 가격표와 주변 공항을 보여준다.
- `가격 우선`, `편안함 우선`, `균형`으로 정렬한다.
- 가격, 조회 시각, 통화, 수하물, 경유, 공항 변경, 환불 조건을 표시한다.
- 목표가와 감시 시간을 저장하고, 목표가 도달 또는 큰 변동 때 알린다.
- 자동 예약·결제는 하지 않고 공식 예약 링크로 이동시킨다.

### 일정·숙소 추천

- 항공 도착·출발 시각을 반영해 첫날과 마지막 날의 강도를 낮춘다.
- `느긋한 여행`, `균형 여행`, `많이 보는 여행` 3안을 만든다.
- 장소별 영업시간·이동시간·휴식시간을 함께 보여준다.
- AI 결과는 제안 상태로 표시하고, 참여자가 수정·댓글·선택한 뒤 확정한다.

### 공동 편집

- 일정 항목에 제안자·수정자·최종 확정자를 남긴다.
- 동시에 수정할 때는 자동으로 덮어쓰지 말고 변경 내용을 보여준다.
- 장소는 `필수`, `가면 좋음`, `보류`로 구분한다.
- 예산은 전체·개인별·공동비용을 구분하되, 금액 공개는 별도로 동의 받는다.

### 여행 중

- 첫 화면에는 오늘의 다음 행동 하나만 크게 표시한다.
- `여기로 가기`, `호텔 주소 보여주기`, `사진 번역`, `환전`, `안부 보내기`, `SOS`를 큰 버튼으로 제공한다.
- 오프라인에서도 확정 일정·호텔 주소·긴급 연락처·티켓을 볼 수 있게 한다.

## 5. easy-travel 적용 우선순위

### P0 — 공동여행의 뼈대

- 여행 소유자·공동 계획자·여행자·보기 전용 권한 모델
- 초대 링크 또는 코드와 참여자별 동의
- 세 가지 여행 시작 방식
- 후보 저장, 제안, 선택, 확정 상태
- AI 일정 3안과 사용자 수정·확정

### P1 — 실제 협업과 알림

- localStorage를 서버 Trip 저장소로 전환
- 참여자별 변경 이력·댓글·투표
- 목표가 기반 서버 항공 감시와 푸시 알림
- 예약정보 사진/PDF OCR과 사용자 확인
- 확정 일정 오프라인 저장 및 항공 지연 시 재계획 제안

### P2 — 여행 중 자동화

- 장소 도착·출발 알림
- 동의 기반 위치 공유와 체크인 이력
- 영수증·결제 문자 분석 후 공동비용 정산
- 실제 항공·숙소 예약 연동

## 6. 벤치마킹에서 지킬 선

- Google Flights·Skyscanner의 화면 흐름은 참고하되 가격을 스크래핑하지 않는다.
- Hopper처럼 “지금 사라”는 예측을 제공하려면 충분한 과거 가격 데이터와 정확도 검증이 필요하다.
- TripIt·Wanderlog처럼 예약을 자동 추출하더라도 사용자가 확인하기 전 확정하지 않는다.
- Life360처럼 위치를 수집하더라도 기본값은 꺼짐이며 공유 대상·기간·목적을 명확히 한다.
- API 결과가 없을 때 데모 가격·가짜 예약·가짜 안전 상태로 대체하지 않는다.
