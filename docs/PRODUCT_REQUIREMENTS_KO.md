# easy-travel 제품 요구사항

> 요구사항 ID는 [검수 계약 문서](./EASY_TRAVEL_OPUS_MVP_REVIEW_SPEC_KO.md)의 PL/EX/RV를 따릅니다. 이 문서는 각 요구사항의 **구현 방법·현실 상태·단계**를 정리합니다.
> 상태 표기: **Live**(실제 동작) · **Mock**(데모 데이터) · **Fallback**(대체 경로) · **미구현**

## 0. 역할

| | 부모님(여행자) | 보호자(자녀) |
|---|---|---|
| 목적 | 지금 할 일 하나 | 준비·비교·확인 |
| 첫 화면 | 다음 장소 + 길찾기 큰 버튼, 숙소로, 통역, 도움 | 여행 상태, 할 일, 가격 감시 |
| 편집 | 없음(도착·완료·안부만 누름) | 계획·일정·숙소·연락처·공유 범위 |
| 글자·버튼 | 본문 20px+, 주요 버튼 60px | 본문 16–17px, 버튼 48px+ |

공통 원칙: 데모는 데모로 표시합니다. “최저가·안전·시세”는 근거와 범위를 함께 씁니다. 사용자가 확인하기 전에는 자동으로 확정하지 않습니다. 권한(위치·카메라·마이크·알림)은 쓰는 순간에 따로 물어봅니다.

## 1. 계획

| ID | 요구 | 구현 방법 | 현재 | 단계 |
|---|---|---|---|---|
| PL-01 | 여행 조건 수집 | 지금 받는 항목: 목적지·출발지·날짜·인원·예산·선호. 추가할 항목: 출발 IATA, 직항/경유 허용, 하루 걷기 한도, 계단 회피, 짐 양, 출발 시간대. 건강 관련 설명은 받지 않고 “걷기 한도” 같은 행동 기준으로만 받음 | 일부 Live, 날짜 검증 추가 | P1 |
| PL-02 | 항공 탐색·비교 | `FlightOffer`(요청서 타입) → 정렬 기준: 최저가 / 직항 / 피로도 최소 / 수하물 포함 총액. 도착 공항과 현지 도착일 표시 | Mock(목적지별) | P1 Mock 확장 → P3 Live |
| PL-03 | 가격 감시 | 결과 저장과 감시 등록을 분리. 조건 확인 후 `활성화`. `searchCriteriaHash`·`targetPrice`·`bestSeenPrice`·`lastCheckedAt`·`nextCheckAt`·`notificationStatus`. 트리거: 목표가 이하 / 비교 가능한 직전값보다 10% 하락(바꿀 수 있음). **공급자 약관이 자동 조회를 허용할 때만** 실제 감시를 켬 | Mock(설정만) | P3 |
| PL-04 | 항공과 연계한 호텔 추천 | 입력: 도착·출발 현지시각, 체크인·아웃, 객실, 예산, 주요 방문지. 패키지 3종: **편안한 이동**(늦은 도착이면 공항 접근·늦은 체크인), **이동 부담 적음**(일정 중심·역 접근), **예산 절감**(숙박+교통 총액, 계단·장거리 경고). 체크인 시각보다 늦게 도착하면 “늦은 체크인 확인 필요” 표시 | 미구현 | P1(Mock 조건 추천) → P3 |
| PL-05 | 실행 가능한 일정 | 일정 항목: 날짜·현지 시간대·좌표/Place ID·체류·이동 모드·예약 필요·휴식·대체안·확정 상태. 부모님 기본값: 하루 핵심 2곳 이하, 점심·휴식 블록, 첫날 도착·체크인, 마지막 날 공항 시간. 지도 API 없이 “25분” 같은 수치를 지어내지 않음 | Mock 템플릿(“지하철 25분” 같은 지어낸 수치 제거) | P1 |
| PL-06 | 예산·문서·가족 확정 | 항목별 예산(항공·숙박·공항 교통·현지 교통·식비·관광·예비비), 확정 금액과 추정 금액 구분, 예약번호 일부 마스킹 | 단일 추정 금액 | P1 |

### 이동 피로도와 총비용 (PL-02·PL-04 공통)

- **피로도 0–10**: 비행시간, 경유 횟수와 대기, 야간 비행, 8시 전 출발 / 22시 후 도착, 시차, 공항→숙소 환승 수, 하루 걷는 시간, 하루 이동 구간 수. 각 요인 점수와 이유 2줄을 함께 보여줍니다.
- **총비용**: 항공 + 숙박 + 공항 왕복 + 현지 교통 + 식비·입장료 추정. 항목마다 출처(조회/추정)를 표시합니다.
- **정렬**: 보호자가 “편안함 우선 / 균형 / 비용 우선”을 고르면 가중치만 바뀝니다. 계산은 순수 함수와 테스트로 고정합니다(외부 API 없이 Mock으로 먼저 검증).

## 2. 여행 중

| ID | 요구 | 구현 방법 | 현재 | 단계 |
|---|---|---|---|---|
| EX-01 | 지금 할 일 대시보드 | 목적지 시간대 기준 “오늘 Day N”, 지금/다음/완료/건너뜀. 가장 큰 버튼은 다음 장소 길찾기 | 오늘 Day 계산·다음 장소 선택 Live(로컬) | P0 일부 → P1 |
| EX-02 | 사진으로 장소 찾기 | JSON 응답(`후보{이름, 현지 표기, 신뢰도, 근거}` 1–3개) 서버 검증 → 후보마다 지도/길찾기/일정 추가. 동의하면 현재 위치(대략)를 함께 보냄. 사진만으로 좌표를 단정하지 않음 | 자유 텍스트 Live/Fallback | P1 |
| EX-03 | 상품·가격 확인 | 세 값을 분리: ① 표시 가격(사용자 확인) ② 원화 참고액(환율 기준일·출처) ③ 시세 판단은 **같은 상품·용량·조건의 근거가 있을 때만**, 없으면 “판단할 자료가 부족해요” | 미구현(환전 계산만 Live) | P3 |
| EX-04 | 양방향 음성 통역 | 큰 버튼 두 개(“한국어로 말하기” / “현지 사람 말 듣기”). 녹음 → STT 원문 확인 → 번역 → 큰 글씨 → 사용자가 누르면 TTS. STT: Web Speech API(iOS는 `webkitSpeechRecognition`) → 미지원이면 OpenRouter `/api/v1/audio/transcriptions` → 실패하면 텍스트·자주 쓰는 말. TTS: `speechSynthesis` → 대안으로 OpenRouter `/api/v1/audio/speech`. 녹음은 저장하지 않음 | 텍스트 단방향 Live | P1 텍스트 양방향 → P1 음성(실기기 검증) |
| EX-05 | 일정 진행·재계획 | 상태 `planned|in_progress|arrived|completed|skipped|delayed`. 부모님이 누르는 기록이 기본이고, 늦으면 “다음 장소를 미룰까요?”를 제안해 사용자가 확정. 실시간 교통시간은 지어내지 않음 | 상태 필드만 준비 | P1 |
| EX-06 | 숙소 도착 알리기 | “숙소에 도착했어요” 버튼 → (선택) 1회 위치 → “숙소 근처에서 확인됨 / 위치 미확인” → 사용자 확인 기록. 보호자 전송은 실제 채널이 준비된 뒤에만 하고, 기록 성공과 전송 성공을 따로 표시. 미응답은 “미확인”이지 “위험”이 아님 | 미구현(수동 안부 기록만) | P1 기록 → P2 전송 |
| EX-07 | 오프라인 필수 정보 | PWA 캐시 + 로컬 Trip: 오늘·내일 일정, 숙소 이름·주소·현지어 표기, 긴급번호, 자주 쓰는 말, 마지막 동기화 시각 | 로컬 저장만(오프라인 앱 셸 없음) | P1 |

## 3. 귀가 후

| ID | 요구 | 구현 방법 | 현재 | 단계 |
|---|---|---|---|---|
| RV-01 | 여행 타임라인 | 완료·건너뜀 기록 + 안부·도착 + 사용자가 고른 사진·한 줄 소감. 사진첩 전체 접근 금지 | 미구현 | P1 |
| RV-02 | 실제 비용 | 여행 중 빠른 지출 입력(금액·통화·분류·결제자) + 영수증 비전 추출 → 미확정 후보 → 사용자 확정. 예산 대비 분류별 차이, 1인 분담, 참고 환율과 카드 실제 원화 구분 | 미구현 | P1(직접 입력) → P3(영수증) |
| RV-03 | 평가·다음 여행 | 편의성·걷는 양·숙소 접근성·통역 사용성·비용 만족도를 쉬운 선택형으로. 결과를 “다음 여행 조건” 제안으로 저장하고, 사용자 승인 뒤에만 기본값에 반영 | 미구현 | P1 |
| RV-04 | 공유형 요약 | 한 페이지 요약(일정·선택 사진·주요 이동·지출 총액·다음 개선점). 공유 전에 공유 범위 확인 | 미구현 | P2 |

## 4. 금지·경계 (유지)

- 실제 예약·결제, 상시 위치 추적, 구조 요청 대행, 사진만으로 만든 현지 시세는 이번 MVP에 넣지 않습니다.
- 여권·카드 번호, 문자 전문, 예약번호 원문, 사진 원본은 기본으로 저장하지 않습니다.
- “안전하게 도착”, “구조 요청 완료”, “최저가 보장” 같은 문구는 쓰지 않습니다.
